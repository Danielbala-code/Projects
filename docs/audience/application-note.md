# How to present this portfolio project

## CV bullet

Built a reproducible customer-engagement lab using Python, SQL and real public transaction data: audited541,909 item rows, engineered chronological customer snapshots, and improved held-out repeat-purchase ranking from0.553 ROC-AUC with a recency rule to0.693 with logistic regression. Added fictional consent/test-control checks, optional local Qwen explanations and a static GitHub Pages dashboard.

## Interview explanation

“The business decision is whom to prioritise for further engagement analysis. I first define an observable outcome and an honest benchmark. I aggregate items into invoices, keep future outcomes out of historical features, and compare a small model on later cohorts. The model improves ranking in this retail dataset, but that is not proof of incremental outreach benefit. Before a campaign, consent and eligibility come first; a randomized experiment would measure actual lift. Qwen explains computed facts for a person to review, rather than inventing or calculating the results.”

For EXL, emphasise SQL customer snapshots, international reporting denominators, quality exception counts and test/control governance. For Sky, emphasise temporal evaluation, simple baselines, discrimination versus probability calibration and seasonal drift. The same methods require approved fan/viewing data and a domain-specific outcome before deployment. Do not describe these retail results as streaming churn or company-specific performance.

## Three honest tradeoffs

- UCI retail was accessible; MIND required access. This kept genuine outcomes but made the demo less direct for OTT/news.
- Four numeric predictors justify logistic regression; embeddings and an agent framework would add complexity without a text-retrieval problem to solve.
- GitHub Pages keeps evidence accessible; Codespaces supports Python and local Qwen while running. Neither is a production campaign system.
